The flow

  1. Each location updates one standard file (same template, fixed file name, no version numbers) in its own shared folder.
  2. The consolidation reads only the raw input sheets (Incidents, Hazard actions, Hours, Submission info) — never local dashboards.
  3. The Data check gate shows READY / CHECK / MISSING per location before anything is reported.
  4. All KPIs are calculated centrally with one formula set, one cut-off date and one set of targets. Locations cannot change regional logic.
  5. Reports (slides / dashboard) are linked only to the calculated report sheets, so a refresh updates everything.

Monthly routine (~10 minutes)

  1. Locations fill their file and set status = Submitted.
  2. Regional owner sets the reporting month → Refresh all.
  3. Data check: all READY? If not, the location fixes its file → refresh again.
  4. Update report links → export PDF.

Calculation rules

  • Counted incident = Type LTI / MTI / FAI / Near Miss, not excluded (commuting, contractor/vendor), valid standard risk family, real date, not an EX- example row.
  • LTIF = LTI × 200,000 / hours
  • TRIR = (LTI + MTI) × 200,000 / hours
  • Severity rate = lost days × 200,000 / hours (lost days counted in the month of the incident)
  • Regional rates use TOTAL injuries and TOTAL hours of all locations — never an average of location rates.
  • Hazard reports = unique hazard IDs (one hazard can have several action rows; each action is tracked separately).
  • Overdue = In Progress / Not Started with due date before the cut-off date (end of reporting month).
  • Blank hours = not reported → rate shown as Provisional, never as zero.
  • Year-on-year compares the same months (Jan → reporting month) of both years, so locations must keep last year's data in their file.
